Moved out of CLAUDE.md on 2026-08-04 to cut the auto-loaded context floor
(~28k -> ~5k tokens per session). **CLAUDE.md keeps the package index and the
verdicts; this file holds the detail.** If a package's PURPOSE or VERDICT changes,

- `db_retry.py` — `connect_with_retry` / `is_lock_conflict`. DuckDB allows one writer, and the unattended jobs contend for it: signal-watch opens ~10 connections per run, xsmom syncs thrice daily, and the web backend takes a write lock at startup and on the stats-cache refresh. Because every timer is `Persistent=true`, a resume from suspend fires several catch-ups **in the same second** rather than on their staggered schedules — that is how `buibui-xsmom-daily` died on 2026-08-11 (both timers report a last trigger of 09:27:34). Retrying at connect time covers whichever job holds the lock; a fix aimed at one holder does not. Budget ~52s over 6 attempts, sized to outlast a full signal-watch run. **Only `Conflicting lock` is retried** — DuckDB raises a bare `IOException` for every I/O failure, so a bad path must still fail immediately rather than a minute later. Wired into `analytics_runner._open_session`; `recalibrate_runner` and `signal/` still connect directly.

Signs the **causally demeaned** remaining return (expanding mean over strictly earlier weeks) and collapses the cross-section to **one observation per calendar week**, since 6,000 symbol-weeks are nowhere near independent.
