Moved out of CLAUDE.md on 2026-08-04 to cut the auto-loaded context floor
(~28k -> ~5k tokens per session). **CLAUDE.md keeps the package index and the
verdicts; this file holds the detail.** If a package's PURPOSE or VERDICT changes,

- `trade/` — execution layer (P3 XS-solo live wiring, sub-project #3 slice 2 + #4). Turns the read-only `analytics/xsmom/live.py::TargetBook` into overlay-gated Binance Futures orders; consumes the XS book while keeping `analytics/xsmom/` pure/read-only. `routing.py` (PURE: `build_order_plan` — `TargetBook` + current positions + mark prices + exchange filters → `OrderPlan`; market-order Δqty with LOT_SIZE rounding — the helper itself now lives at `portfolio/sizing.py::round_down_to_step`, shared with the F2 card post-pass so router and card round identically rather than through two copies that can drift. **That helper is deliberately not a plain `floor(q/step)*step`** — see the CRITICAL note in `CLAUDE.md`; this router is the call site that made it matter, because `delta_qty = target_qty - current` is a difference of two step multiples and so is an exact multiple *every* time, the one input class the naive form shaves — no-trade band + min-notional/min-qty skips, `reduce_only` on trims/closes but not intended flips). `overlay.py` (PURE fail-closed `evaluate_overlay` — `RiskLimits` six independent guardrails: kill-switch, drawdown halt, gross-leverage cap, per-instrument notional cap, per-run turnover guard, data-staleness guard; any breach blocks the whole plan). `binance_futures.py` (injectable `BinanceFuturesAdapter` over `python-binance` Client; reads positions/equity/filters/marks, writes market orders + sets one-way/cross/leverage; `mode` ∈ {`dry_run` no-op-writes, `testnet`, `live`}; hedge-mode → hard abort). `xsmom_executor.py` (orchestrator `run_once` — state → `replay_targets(capital=live-equity, now=clock)` → plan → overlay → submit with per-order isolation; current gross from positions×marks with a `None`→steady-state-cap fail-safe when a held position's mark is missing; gitignored JSON state file = peak-equity high-water mark + kill-switch + last-run). Driver `tools/xsmom_execute.py` (`make buibui-xsmom-execute`): **dry-run default** (prints the order plan, submits nothing), `--mode testnet` validates the full write path at zero capital risk, `--mode live` double-gated by `--i-understand-live` + `BINANCE_ALLOW_LIVE=1` (not exercised yet — the mainnet flip is a later supervised slice); overlay defaults recalibrated to the real book envelope: `--vol-target` (0.20 validated; deploy first live cycles at 0.10), `--max-gross-leverage` 4.5, `--min-active-positions` 15 breadth guard (aborts on a thin/degenerate cross-section), `--capital` (size the book off a fixed capital instead of live account equity — threads into `run_once(capital_override=)`; for a capital-matched testnet vs real-account A/B, since position discretization is capital-dependent; omit for live = real equity; default unset is byte-identical. **A pinned run must NEVER move `peak_equity`** — it is a hypothetical and the ratchet is permanent, so a throwaway `--capital` would mutate a safety control: measured 2026-08-06, one `--capital 5000` against a 1201.33 account left peak 5000.00 / floor 3750.00 standing, which halts the book even if the account triples. The pinned equity IS still compared against the existing peak, so the halt itself still applies, and `last_run.capital_override` records the pin because `last_run` keeps only the last run — without it a poisoned peak is undiagnosable. A/B runs deliberately share the ONE state file: `kill_switch` lives there, and a kill switch that skipped pinned runs would be a worse hole), auto-detected cold-start turnover allowance (lets the full book establish on day 1 without tripping the steady-state churn guard). **Daily workflow:** `make buibui-universe-sync` (`analytics sync --universe --timeframes 1d` — the XS book runs on 1d only, which `analytics sync`'s default `1h 4h` never refreshes, silently degenerating the book to majors-only) then `make buibui-xsmom-daily` (universe 1d sync + executor dry-run in one command). Output is a book-centric Rich table (one row per active leg incl. in-band holds, sorted by |notional| desc; columns SYM/SIDE/CUR→TGT-leverage/$NOTIONAL/Δ$/MARK/FCAST/ACTION) under a GOV/GROSS/NET-leverage summary header; the overlay-blocked case still renders the table beneath the abort banner. `trade/open_trades.py` and its `make buibui-open-trades` target were REMOVED 2026-08-11: the file was 0 bytes and the target ran it after printing a banner, so it **exited 0 having done nothing** — a declared surface nothing executed and nothing asserted about. The fork hit the identical defect (wifey #138/#140).
- `deploy/` — 24/7 VPS deploy kit (systemd timers, **not** Docker; design `docs/superpowers/specs/2026-06-25-vps-deployment-design.md`, runbook `deploy/README.md`). Two timers replace the unreliable GitHub Actions cron — `buibui-signal-watch` (every 15 min, `signal watch --once --telegram --catch-up`, Binance-direct) + `buibui-xsmom` (daily 00:10 UTC, universe 1d sync → XS executor); `Persistent=true` reruns a job missed during downtime/reboot (the exact GHA silent-non-trigger failure mode). `deploy/systemd/user/` holds the **user-scope laptop variants — the deployment actually live today**, the VPS being deferred. **Five timers as of 2026-08-07j** (`buibui-backup-offsite` and `buibui-daily-check` joined the three below), and the schedules encode an asymmetry worth knowing: `buibui-signal-watch` (every 15 min) must be punctual because a missed candle is *permanent* evidence loss (the N8 watermark drags past it), whereas `buibui-xsmom-daily` (00:20/02:20/06:20 UTC, universe 1d sync + executor dry-run) and `buibui-backup` (07:40/12:40 UTC) lose **nothing** by running late — the sync is incremental and the snapshot is a point-in-time copy — so those fire repeatedly and cheaply instead of once precisely, which is what covers a laptop that wakes with no wifi. Every non-signal-watch schedule avoids `:01/:16/:31/:46`, where signal-watch holds an exclusive DuckDB lock that on 1.5.5 refuses a second *process* even read-only. They add `--catch-up` (a laptop *creates* gaps, so without it a suspend costs ledger evidence rather than merely a late scan) — **and note the live units carry that flag in `ExecStart` directly, bypassing `run-signal.sh` entirely, which is why that script sat without it until 2026-08-07i: the omission was real but latent, reachable only on the VPS path nothing uses yet. Both now agree.** They fire at `*:01/15`, pin an explicit `PATH` (user units get a minimal one that cannot find linuxbrew's `poetry`, which `run-job.sh` needs on its *failure* path — so the alert about a broken run would itself break) and a `SyslogIdentifier` (else journald tags lines with the executable name and `journalctl --user -u` returns nothing), and **deliberately omit `network-online.target`**: that target does not exist in the systemd user manager at all, and even in system scope it is a boot-time barrier that stays active across suspend and never re-arms on resume — so the committed VPS units carry the same latent race and are immune only because a VPS never suspends. `run-job.sh` wraps each job with a bounded resolver-readiness gate, then a healthchecks.io dead-man's-switch + Telegram-on-fail; the gate exists because `Persistent=true` fires the missed run the *instant* the user manager resumes, and on 2026-08-06 an ~18s window in which nothing resolved killed all three network legs at once (the `/start` ping, the job on a DNS `NameResolutionError`, and the `/fail` ping — so healthchecks saw NO ping rather than a failed one). It sits ahead of the pings, where a unit-level dependency never reached, and is bounded + outcome-preserving (`NET_WAIT_SECS` 60 / `NET_WAIT_INTERVAL` 2 / `NET_WAIT_HOSTS` `api.telegram.org`, first host to resolve wins): a genuine outage still fails exactly as before, just later — the gate changes only TIMING, never the exit code, so it cannot mask a real network failure; `run-signal.sh` / `run-xsmom.sh` workload scripts (**`run-xsmom.sh` had no `PYTHONPATH` until 2026-08-07**, so the *executor* half of the daily workflow always died `ModuleNotFoundError: No module named 'analytics'` while the sync half above it succeeded — a split failure that went unnoticed because the job did real work first, and that surfaced only the first time the script ran under systemd rather than by hand); `backup-analytics.sh` (verified local snapshot of `analytics.db` + the `LEDGERS` files + the `LEDGER_DIRS` directories to `BUIBUI_BACKUP_ROOT`. **Both arrays have been expanded TWICE — 2026-08-08 from 4 entries to 10 files + 3 dirs, and 2026-08-11 to 17 files + 7 dirs.** The recurrence is the durable lesson: **an allowlist over a single-copy tree defaults to UNCOVERED**, so a newly-created artifact stays invisible until someone diffs the backup against the live tree — which is how BOTH audits found their gap and is the only way the next one gets found. Cost never kept anything out; the 2026-08-11 additions total ~300KB against a 264MB snapshot. That round added `regime-log.jsonl` (append-only and unreconstructible — it holds the first regime turn this system ever dated), `task-marks/` (same watermark class as the three ledgers below: a missing marker reads as OVERDUE, so losing it re-presents every weekly cadence at once), `daily_check.py` and `next-conversation-prompt.md` (the health-check system and the handoff, both single-copy), plus `scratch/`, `chart-drops/`, `xsmom_targets/` and four research docs. Three exclusions are documented in the script itself so the next audit does not re-find them as misses. The first expansion followed an audit that found the whole ingest pipeline uncovered — Streams A/B (`thesis-inbox.md`, `mechanics-backlog.md`), all 65 video-notes, all 23 journal entries, `external-context/`, and the three watermark/dedup ledgers `yt-feed-state.json` / `routed-ledger.json` / `.cache/chart-drops/processed.json`. Every one is gitignored and single-copy, so the arrays ARE the only copy. The dedup ledgers lose no past data when destroyed but silently change future behaviour (consumed videos re-present, re-ingests double-write, handled chart drops re-ingest), and `processed.json` sits under `.cache/` where a routine cleanup wipes it. Directories must go in `LEDGER_DIRS`: the file loop is `[ -f ]`-guarded and skipped a directory silently, which is the mechanism by which the gap existed, default `~/backups/buibui`, retention `BUIBUI_KEEP_DAILY` 14 / `BUIBUI_KEEP_WEEKLY` 8. Primary method is DuckDB's own `COPY FROM DATABASE`, **not `cp`** — measured 4.6s/258MB against 0.6s/320MB, buying a transactionally consistent read and a repack, with the byte copy kept only as the lock-free fallback. Snapshots are **staged and renamed**, never written in place: a laptop crash on 2026-08-07 killed a run mid-copy and left a 100MB directory at the final path that DuckDB **opened without error and reported ZERO tables** — the identical failure that makes the committed `live_signal.duckdb` useless as a backup, and one that a naive "does today's backup exist" check reads as green. `MANIFEST.json` is written last, so its presence is the trust signal `daily_check.py` reds on. Weekly `EXPORT DATABASE` to parquet (~111MB) guards against DuckDB storage-format drift; both restore paths are round-trip tested. **Local leg only**, which is why `backup-offsite.sh` exists beside it); `backup-offsite.sh` (the off-machine leg, 2026-08-07j — `rclone sync` of `BUIBUI_BACKUP_ROOT` to `BUIBUI_BACKUP_REMOTE`, driven by `buibui-backup-offsite.timer` at 13:25 UTC, ~45 min after the local fire so the day's snapshot exists first. It **exits 1 while the remote env var is unset**, deliberately: an enabled-but-unconfigured timer must complain daily rather than look green while nothing is copied, since `rclone config` is interactive and cannot be scripted. It runs `sync`, so remote retention tracks local retention — and therefore **mirrors deletions**, which is why it refuses to run when no `MANIFEST.json` exists under the backup root. Syncing an empty tree would delete the only remote copy, turning a local bug into total loss; that guard is proven by injection, not by inspection, and must not be removed); `daily_check.py` is pushed by `buibui-daily-check.timer` (09:10 UTC, **once** daily at an hour the operator can act on — a nudge that fires while he is asleep is one he learns to ignore) with `--exit-on-tier2`, because tier-2 lines do not set exit 1 and the push would otherwise be silent on chart-drops and external-context, the exact staleness it was built to catch; the interactive contract is unchanged; `harden.sh` (UFW / fail2ban / unattended-upgrades / sshd, lock-out-guarded); `oci-retry-launch.sh` (loops the launch API across all ADs until the contended free Oracle A1 shape frees up, auto-discovers the Ubuntu 24.04 aarch64 image, Telegram-pings on success). Live trading keys live ONLY on the box, never in GHA secrets; mode sequences `dry_run` → testnet soak → supervised mainnet flip (`.env` `EXEC_MODE` / `EXEC_CAPITAL` / `EXEC_EXTRA_ARGS`).
- `monitor/` — monitor modules split into thin wrappers and pure logic libs:
  - `price_monitor.py` / `position_monitor.py` — thin wrappers (create client, load config, call lib)
  - `price_lib.py` / `position_lib.py` — pure business logic with dependency injection (no module-level side effects). `position_lib` merges the classic (`/fapi/v1/openOrders`) and algo (`/fapi/v1/openAlgoOrders`) books for SL/TP; `normalize_conditional_orders` maps algo rows to the classic shape, including the size (algo spells it `quantity`, classic `origQty`) and `closePosition`. `uncovered_position_qty` measures stop COVERAGE rather than price — working stop quantity on the matching position side vs position size — so a partially re-armed trail renders `⚠ <price> (N% naked)` in the SL column (J2, from the 2026-08-04 incident where a phone trail re-armed only the original entry qty and left the adds unstopped for 4h). `closePosition` stops count as full cover regardless of quantity; take-profits never count. **Unknown coverage must never render as unprotected** — the per-symbol price-only fallback in `fetch_open_positions` sets `orders=None` and the check stays silent, because a warning on every position is one the operator learns to ignore
  - `live_price.py` — WebSocket + Rich live mode for price monitor
  - `live_position.py` — WebSocket + Rich live mode for position monitor
- `utils/` — shared utilities:
  - `binance_client.py` — Binance client creation, time sync, config loading; `create_data_client()` dispatches on `DATA_SOURCE` (`okx`→`OKXClient`, else Binance)
  - `okx_client.py` — keyless OKX V5 public market-data adapter; `OKXClient.futures_klines()` returns Binance-shaped OHLCV (backward pagination via `after`, drops unconfirmed candle, `1d`→`1Dutc`, neutral `taker_buy_volume=volume/2`). `analytics.data_fetcher.fetch_klines` branches on `isinstance(client, OKXClient)`; `KlineClient = Client | OKXClient` type alias. Funding/OI intentionally not implemented (no live detector needs them on the OKX path)
  - `config_validation.py` — coins.json schema validation
  - `telegram.py` — Telegram message sending
  - `live_store.py` — shared in-memory store for live WebSocket data
  - `live_loop.py` — shared Rich live display loop logic
