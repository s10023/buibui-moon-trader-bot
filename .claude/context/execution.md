# Execution, Deploy and Monitoring Reference

Moved out of CLAUDE.md on 2026-08-04 to cut the auto-loaded context floor
(~28k -> ~5k tokens per session). **CLAUDE.md keeps the package index and the
verdicts; this file holds the detail.** If a package's PURPOSE or VERDICT changes,
update CLAUDE.md too — the index is the only path a session has to this file.

- `trade/` — execution layer (P3 XS-solo live wiring, sub-project #3 slice 2 + #4). Turns the read-only `analytics/xsmom/live.py::TargetBook` into overlay-gated Binance Futures orders; consumes the XS book while keeping `analytics/xsmom/` pure/read-only. `routing.py` (PURE: `build_order_plan` — `TargetBook` + current positions + mark prices + exchange filters → `OrderPlan`; market-order Δqty with LOT_SIZE rounding, no-trade band + min-notional/min-qty skips, `reduce_only` on trims/closes but not intended flips). `overlay.py` (PURE fail-closed `evaluate_overlay` — `RiskLimits` six independent guardrails: kill-switch, drawdown halt, gross-leverage cap, per-instrument notional cap, per-run turnover guard, data-staleness guard; any breach blocks the whole plan). `binance_futures.py` (injectable `BinanceFuturesAdapter` over `python-binance` Client; reads positions/equity/filters/marks, writes market orders + sets one-way/cross/leverage; `mode` ∈ {`dry_run` no-op-writes, `testnet`, `live`}; hedge-mode → hard abort). `xsmom_executor.py` (orchestrator `run_once` — state → `replay_targets(capital=live-equity, now=clock)` → plan → overlay → submit with per-order isolation; current gross from positions×marks with a `None`→steady-state-cap fail-safe when a held position's mark is missing; gitignored JSON state file = peak-equity high-water mark + kill-switch + last-run). Driver `tools/xsmom_execute.py` (`make buibui-xsmom-execute`): **dry-run default** (prints the order plan, submits nothing), `--mode testnet` validates the full write path at zero capital risk, `--mode live` double-gated by `--i-understand-live` + `BINANCE_ALLOW_LIVE=1` (not exercised yet — the mainnet flip is a later supervised slice); overlay defaults recalibrated to the real book envelope: `--vol-target` (0.20 validated; deploy first live cycles at 0.10), `--max-gross-leverage` 4.5, `--min-active-positions` 15 breadth guard (aborts on a thin/degenerate cross-section), `--capital` (size the book off a fixed capital instead of live account equity — threads into `run_once(capital_override=)`; for a capital-matched testnet vs real-account A/B, since position discretization is capital-dependent; omit for live = real equity; default unset is byte-identical), auto-detected cold-start turnover allowance (lets the full book establish on day 1 without tripping the steady-state churn guard). **Daily workflow:** `make buibui-universe-sync` (`analytics sync --universe --timeframes 1d` — the XS book runs on 1d only, which `analytics sync`'s default `1h 4h` never refreshes, silently degenerating the book to majors-only) then `make buibui-xsmom-daily` (universe 1d sync + executor dry-run in one command). Output is a book-centric Rich table (one row per active leg incl. in-band holds, sorted by |notional| desc; columns SYM/SIDE/CUR→TGT-leverage/$NOTIONAL/Δ$/MARK/FCAST/ACTION) under a GOV/GROSS/NET-leverage summary header; the overlay-blocked case still renders the table beneath the abort banner. `trade/open_trades.py` is an unused empty stub (legacy `make buibui-open-trades`).
- `deploy/` — 24/7 VPS deploy kit (systemd timers, **not** Docker; design `docs/superpowers/specs/2026-06-25-vps-deployment-design.md`, runbook `deploy/README.md`). Two timers replace the unreliable GitHub Actions cron — `buibui-signal-watch` (every 15 min, `signal watch --once --telegram`, Binance-direct) + `buibui-xsmom` (daily 00:10 UTC, universe 1d sync → XS executor); `Persistent=true` reruns a job missed during downtime/reboot (the exact GHA silent-non-trigger failure mode). `run-job.sh` wraps each job with a healthchecks.io dead-man's-switch + Telegram-on-fail; `run-signal.sh` / `run-xsmom.sh` workload scripts; `harden.sh` (UFW / fail2ban / unattended-upgrades / sshd, lock-out-guarded); `oci-retry-launch.sh` (loops the launch API across all ADs until the contended free Oracle A1 shape frees up, auto-discovers the Ubuntu 24.04 aarch64 image, Telegram-pings on success). Live trading keys live ONLY on the box, never in GHA secrets; mode sequences `dry_run` → testnet soak → supervised mainnet flip (`.env` `EXEC_MODE` / `EXEC_CAPITAL` / `EXEC_EXTRA_ARGS`).
- `monitor/` — monitor modules split into thin wrappers and pure logic libs:
  - `price_monitor.py` / `position_monitor.py` — thin wrappers (create client, load config, call lib)
  - `price_lib.py` / `position_lib.py` — pure business logic with dependency injection (no module-level side effects)
  - `live_price.py` — WebSocket + Rich live mode for price monitor
  - `live_position.py` — WebSocket + Rich live mode for position monitor
- `utils/` — shared utilities:
  - `binance_client.py` — Binance client creation, time sync, config loading; `create_data_client()` dispatches on `DATA_SOURCE` (`okx`→`OKXClient`, else Binance)
  - `okx_client.py` — keyless OKX V5 public market-data adapter; `OKXClient.futures_klines()` returns Binance-shaped OHLCV (backward pagination via `after`, drops unconfirmed candle, `1d`→`1Dutc`, neutral `taker_buy_volume=volume/2`). `analytics.data_fetcher.fetch_klines` branches on `isinstance(client, OKXClient)`; `KlineClient = Client | OKXClient` type alias. Funding/OI intentionally not implemented (no live detector needs them on the OKX path)
  - `config_validation.py` — coins.json schema validation
  - `telegram.py` — Telegram message sending
  - `live_store.py` — shared in-memory store for live WebSocket data
  - `live_loop.py` — shared Rich live display loop logic
