# Tools Reference — `tools/`

Moved out of CLAUDE.md on 2026-08-04 to cut the auto-loaded context floor
(~28k -> ~5k tokens per session). **CLAUDE.md keeps the package index and the
verdicts; this file holds the detail.** If a package's PURPOSE or VERDICT changes,
update CLAUDE.md too — the index is the only path a session has to this file.

One-shot analysis and audit scripts. **Not part of the daemon or CLI surface** — each
is run directly, and most are read-only over `analytics.db`.

Stop-gap until a Stats UI card lands. Run via `PYTHONPATH=. poetry run python tools/live_outcomes_report.py [--days N] [--min-n N]`.
  - `journal_fetch.py` — read-only Binance Futures trade reconstructor backing the API-assisted `/journal-trade` v2 (spec `docs/superpowers/specs/2026-06-21-journal-trade-api-assist-design.md`). Pure `group_fills` groups raw `futures_account_trades` fills per (symbol, positionSide) into closed round-trips + open positions (handles adds / partial exits / flip-through-zero), enriched with funding (`futures_income_history`), open-position entry/mark (`futures_position_information`), and open-order exchange SL/TP; flags `already_journaled` against existing journal frontmatter so the `/journal-trade` skill pre-fills the mechanical fields and leaves judgement to the human. Never places/cancels orders; no DB/schema change. Run via `PYTHONPATH=. poetry run python tools/journal_fetch.py [--days N] [--symbol SYM ...] [--json] [--include-journaled]`.
    - **Stop-loss history (J1, 2026-08-07).** `exchange_sl` used to be `None` for **every closed round-trip**: only `openAlgoOrders` was wired and a closed position has no resting orders left. `fetch_algo_orders` now pages `/fapi/v1/allAlgoOrders` (see the cap note below) and `attach_stop_history` fills **`sl_history`** — `{ts, trigger_price, qty, status, source}` oldest-first — plus **`initial_sl`** (the stop in force AT ENTRY) and `exchange_sl` (the LAST working stop). Both ends are kept because the R basis differs by up to **4.7x** between them and the settled journal rule scores against entry while noting the trailed R beside it. `source` comes from the `clientAlgoId` prefix — `stToAg_*` = exchange-attached (`auto`), `ios_*` = phone (`phone`), else `manual` — and is the only field saying WHO moved a stop. `status` (`CANCELED` / `EXPIRED` / `FINISHED`) is what distinguishes a stop-out from a manual exit. For an OPEN position the resting-order path still wins, including when it yields `None`: that genuinely means nothing is protecting the position. A failed window degrades to partial history with a stderr warning, never an abort.
    - **Binance Futures account-history retention — THREE tiers, and picking the wrong one silently changes what you are measuring.** Established by the ST14 self-audit (2026-08-06); the figures it produced stay gitignored, the method is here because every future account-history task inherits it. `/fapi/v1/userTrades` retains roughly the **last 83 days** (fills: maker/taker, notional, size); `/fapi/v1/income` roughly **210 days** (P&L, commission, funding); **`/fapi/v1/income/asyn`** — the async export — reaches **back to account inception** and is the answer whenever the question is "how far back can we go". Recipe: request a downloadId for a **≤1-year** window, poll `income/asyn/id`, download a zipped CSV.
    - **The retention tiers are a measurement trap, not a convenience note.** ST14's first pass scoped itself to `/income`'s 210 days and reached the **opposite** conclusion from the full-history run — not because 210 days was a small sample, but because it was the most **RECENT** one, i.e. a single regime. **Never scope a behavioural audit to whatever the default endpoint happens to retain.**
    - **Three traps, each of which silently corrupts a pull rather than failing:** (1) **`/income` caps at 1000 rows per request and truncates SILENTLY** — it has no window cap (200-day windows work), so a naive fixed-width pager looks like it worked; adaptive halving on any full page recovered **21% more rows** on one year. Always split when `len(batch) == limit`. (2) **An over-old window returns an empty list with NO error**, so `0 rows` never proves you have hit the account's start — corroborate with the shape of the earliest rows (a COMMISSION before any TRANSFER means there was balance before your window, i.e. a wall, not a start). (3) **Rate limiting is aggressive** — four export requests plus 12-second polling earned a 2-minute IP ban (`-1003`); poll at **≥30s** and space the requests.
    - **`GET /fapi/v1/allAlgoOrders` — the stop-history endpoint, and its cap is NOT the one that was filed.** No named python-binance wrapper; call `client._request_futures_api("get", "allAlgoOrders", True, data={...})`. **Corrected 2026-08-07 by measurement:** the filed claim was "a 90-day lookback cap, older `startTime` fails with `-4166`". Both halves are wrong — a `startTime` 200 days back returns rows fine, and `-4166` never appeared. **The real cap is a 7-day INTERVAL (`-4165`, "Maximum time interval is 7 days")**, and how you hit it decides whether you get an error or silent data loss: an explicit `startTime`+`endTime` wider than 7d **fails loudly**, but a `startTime` with **no** `endTime` is **silently clamped to `[startTime, startTime+7d]`** — a 30-day lookback in that form returned a ~6-day slice from the START of the window, dropping every recent stop, with `limit` nowhere near reached so nothing looked truncated. Omitting `startTime` entirely returns only the last 7 days, so it is not a substitute either. **Page in ≤7d windows with an explicit `endTime`, and dedup on `algoId`** — `endTime` is inclusive, so consecutive windows share their boundary instant and a stop armed on one is returned twice, reading as a trail step that never happened. Windows older than ~210d returned 0 rows with **no error**, which cannot be distinguished from "no orders existed" (Binance only migrated conditional orders to this subsystem on 2025-12-09).
